# 1Password、従業員のGitHubアカウント侵害からバックエンドに悪意あるコードを送り込まれ顧客情報の一部が流出

- **日付**: 2026-11-27
- **出典**: [BleepingComputer](https://www.bleepingcomputer.com/news/security/1password-customer-data-stolen-after-employee-github-account-breach/)
- **トピック**: [1Password 従業員GitHubアカウント侵害・バックエンド不正アクセス事案（2026年11月）](../topics/1password-github-backend-breach-2026.md)
- **分類**: 新規

## 概要

パスワード管理サービスの1Passwordは、従業員の業務用GitHubアカウントが侵害され、攻撃者がソースコードへのアクセスとバックエンドサービスへの悪意あるコードの投入を行い、一部顧客の管理系情報を取得したと公表した。保管庫の内容や鍵は影響を受けていないとしている。

## 詳細

### 経緯

- 11月19日: 従業員の業務用GitHubアカウントに関連する不審な活動を検知し調査開始。
- 11月25〜26日: ブログで公表、各メディアが報道。発表は「アップデート」の体裁で、検知から公表まで約6日を要した点を指摘する報道もある。

### 攻撃の流れ

攻撃者はGitHubアクセスを用いてソースコードに到達し、CI/CDパイプラインにもアクセス。バックエンドサービスへ悪意あるコードをプッシュし、そのサービスが一部ユーザーの管理系レコードを取得した。GitHubアカウント自体の侵害手口は公表されていない（フィッシングやクレデンシャルスタッフィングとする一部記事は推測）。ソースコード窃取の範囲も明確ではない。

### 流出した情報

- 氏名、アカウント／ユーザー識別子、アカウント作成日時・最終サインイン日時など
- 招待、プロビジョニング、アカウント回復用のメールリンクに含まれるトークン（少数のユーザー）

1Passwordは、Vault内容（パスワード、シークレット等）、アカウント回復キー、それらを保護する鍵、アプリおよびブラウザ拡張は影響を受けていないと説明。アカウント乗っ取りの証拠も確認していない。

### 対応

侵害されたGitHubアカウントの無効化、窃取されたトークンの失効、影響サービスのクリーンな状態への復元、露出した可能性のあるインフラ認証情報のローテーション／失効、外部専門家による検証。

### 技術的な補足

- 開発者1アカウントの侵害が、CI/CD経由で本番バックエンドへのコード投入に直結した点が核心。ブランチ保護（必須レビュー）、デプロイ承認、ビルド来歴の検証、短命トークン、パイプラインの最小権限が防御線となる。
- ゼロ知識設計（Vaultはクライアント側鍵で暗号化）のため保管データは守られたが、サーバー側が扱うメタデータと回復・招待トークンは別問題。トークンは短寿命・一回限りとし、侵害時に一括失効できる必要がある。
- 利用者は「アカウント保護のため再設定を」等と促す便乗フィッシングに警戒すること。
