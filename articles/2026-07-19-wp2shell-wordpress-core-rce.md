# 「wp2shell」WordPress コア脆弱性、未認証攻撃者によるリモートコード実行が可能に

- **日付**: 2026-07-19
- **出典**: [The Hacker News](https://thehackernews.com/2026/07/new-wp2shell-wordpress-core-flaw-lets.html)
- **トピック**: [wp2shell WordPress コア RCE 脆弱性チェーン（2026年）](../topics/wp2shell-wordpress-core-rce-2026.md)
- **分類**: 新規

## 概要

WordPress コア自体に存在する2つの脆弱性を連鎖させることで、未認証の攻撃者が匿名の HTTP リクエストのみでリモートコード実行を達成できる「wp2shell」と呼ばれる攻撃チェーンが公表された。プラグイン不要の素の WordPress インストールでも悪用可能であり、REST API のバッチルート処理の混同（CVE-2026-63030）と、WordPress コアの SQL インジェクション（CVE-2026-60137）を組み合わせることで、認証を経ずにコード実行まで到達する。

## 詳細

### 脆弱性の内容

- **CVE-2026-63030**: WordPress REST API のバッチルート処理における混同（confusion）の脆弱性。複数の API リクエストをまとめて処理するバッチエンドポイントの権限・コンテキスト分離が不十分であり、本来他のエンドポイントに対して要求される認証チェックを回避できる。
- **CVE-2026-60137**: WordPress コア内の SQL インジェクション脆弱性。

これら2つを連鎖させることで、匿名の HTTP リクエストから任意コード実行（RCE）まで到達する攻撃チェーンが「wp2shell」と名付けられた。Rapid7 の分析によれば、CVE-2026-63030 が起点となり REST API のバッチルート処理を通じて本来到達できないはずの内部処理に到達し、CVE-2026-60137 の SQL インジェクションを介してデータベース操作からコード実行へとつなげる。

### 影響範囲と深刻度

脆弱性は WordPress コアに存在するため、サードパーティ製プラグインやテーマを一切導入していない「素の」WordPress インストールであっても悪用可能とされる。世界の Web サイトの4割以上を占めるとされる WordPress のシェアを踏まえると、影響範囲は極めて広い。

### 悪用状況

2026年7月18日時点で、脆弱性の詳細なメカニズムが公開され、概念実証（PoC）コードも公開状態にある。さらに、永続的オブジェクトキャッシュ（persistent object cache）を利用する環境において追加の悪用条件が成立するケースが確認されている。Cloudflare は WAF ルールを通じて同脆弱性の悪用トラフィックからの保護を開始したと発表しており、既に実環境での悪用の兆候が観測されていることを示唆している。

### 推奨対策

- WordPress コアおよび関連コンポーネントを最新版に速やかに更新する
- REST API バッチエンドポイントへの外部アクセスを制限する、または WAF でフィルタリングする
- 永続的オブジェクトキャッシュ（Redis/Memcached 等）を利用している環境は追加の悪用条件に該当しないか確認する
- サーバーログにおいて REST API バッチルートへの異常なリクエストパターンを監視する
