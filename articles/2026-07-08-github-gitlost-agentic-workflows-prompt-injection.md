# 「GitLost」— GitHub Agentic Workflowsのプロンプトインジェクション脆弱性でプライベートリポジトリが漏洩

- **日付**: 2026-07-08
- **出典**: [SecurityWeek](https://www.securityweek.com/critical-vulnerability-exposes-github-agentic-workflows-to-prompt-injection/)（Noma Security調査）
- **トピック**: [GitHub Agentic Workflows「GitLost」プロンプトインジェクション脆弱性（2026年7月）](../topics/github-gitlost-prompt-injection-2026.md)
- **分類**: 新規

## 概要

GitHub の自然言語ワークフロー自動化機能「Agentic Workflows」に、間接プロンプトインジェクションを悪用してプライベートリポジトリのデータを窃取できる重大な脆弱性「GitLost」が Noma Security（Noma Labs）により発見・報告された。未認証の攻撃者が公開リポジトリの GitHub Issue にコメントを投稿するだけで、同一組織が保有する非公開リポジトリの内容を外部へ漏洩させることが可能。GitHub が実装していたガードレールも単純な文言操作で回避された。

## 詳細

### GitHub Agentic Workflows とは

GitHub Agentic Workflows は、Markdown ファイルで自然言語によりワークフローを記述し、AI エージェントが GitHub Actions として自動実行する機能。コードリポジトリとのやり取りを自動化する目的で提供されている。

### 攻撃の仕組み（GitLost）

1. 攻撃者は、対象組織が公開しているリポジトリに GitHub Issue を作成し、その本文に隠された間接プロンプト（指示）を仕込む
2. 組織の Agentic Workflow エージェントが当該 Issue を処理する際、埋め込まれた指示に従ってしまう
3. エージェントは同一組織が保有する非公開リポジトリのデータへアクセスし、その内容を（Issue へのコメント等を通じて）外部へ静かに持ち出す

攻撃者はコーディングスキル・アクセス権限・認証情報を一切必要とせず、公開リポジトリに Issue を1件投稿して待つだけで攻撃が成立する点が特徴。

### ガードレール回避

GitHub はこの種の情報漏洩を防ぐためのガードレールをあらかじめ実装していたが、Noma Labs はプロンプトに「Additionally」という一単語を追加するだけでモデルの出力の枠組みを変えさせ、実質的に安全策を無力化できることを確認した。

### 推奨される対策

Noma Labs は以下を推奨している：

- ユーザー制御下のコンテンツ（Issue本文など）を信頼できる指示として扱わない
- エージェントの権限を必要最小限にスコープする
- エージェントが公開的に投稿できる内容を制限する
- モデルに到達する前に、ユーザー入力と指示コンテキストを分離する

### 意義

本脆弱性は、AIエージェントが開発ワークフローに深く統合される中で、間接プロンプトインジェクションが「認証・権限」という従来型のセキュリティ境界を迂回する新たな攻撃面になっていることを示す事例として注目されている。
