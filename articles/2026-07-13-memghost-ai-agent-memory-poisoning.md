# 新手法「MemGhost」、1通のメールでAIエージェントに永続的な偽の記憶を植え付け

- **日付**: 2026-07-13
- **出典**: [The Hacker News](https://thehackernews.com/2026/07/new-memghost-attack-plants-persistent.html), [arXiv論文](https://arxiv.org/html/2607.05189v1)
- **トピック**: [MemGhost AIエージェント記憶汚染攻撃（2026年）](../topics/memghost-ai-agent-memory-poisoning-2026.md)
- **分類**: 新規

## 概要

研究者が「MemGhost」と名付けた新たな攻撃手法が報告された。永続的なメモリ機能を持つAIパーソナルエージェントに対し、攻撃者が送信した1通のメールを読ませるだけで、エージェント自身のファイル操作ツールを使って虚偽の情報を「記憶」として書き込ませることができる。ユーザーへの応答には記憶書き込みの痕跡が現れず、後日の別セッションでその偽の記憶がエージェントの応答や行動を誘導する。Open-ClawとGPT-5.4の組み合わせで87.5%、Claude Code SDKとSonnet 4.6の組み合わせで71.4%という高い成功率が確認された。

## 詳細

### 攻撃の仕組み

MemGhost攻撃は、被害者が受信するメール本文に埋め込まれた指示によって成立する。AIエージェントがメールを処理する際、埋め込まれた指示を正規のタスクと誤認し、自身が持つファイル書き込みツールを使って「偽の記憶（false memory）」を永続的なメモリストア（設定ファイルやメモリファイル）に書き込んでしまう。攻撃者は被害者との直接的なやり取りを必要とせず、1通のメールを送るだけの「ワンショット」攻撃として成立する点が特徴。

論文タイトルは「When Claws Remember but Do Not Tell: Stealthy Memory Injection in Persistent Personal Agents」で、攻撃者は標的とする偽記憶の内容だけを与えられた状態で、それを誘導するメール文面を自動生成する手法を確立したとしている。

### ステルス性の理由

- エージェントの内部処理（ファイル書き込み等）はチャット上に表示されないため、ユーザーはメモリが改ざんされたことに気づきにくい
- 多くのユーザーはメモリファイルの中身を直接確認することがない
- エージェントがバックグラウンドでスケジュール実行されている場合、そもそもユーザー宛のメッセージが送られないケースもある

### 影響と検証結果

56件のテストケースを用いた評価で、Open-Claw（GPT-5.4使用）で87.5%、Claude Code SDK（Claude Sonnet 4.6使用）で71.4%のエンドツーエンド成功率を記録した。これは、永続メモリ機能を持つ複数の主要AIエージェントプラットフォームが共通してこの種の攻撃に脆弱である可能性を示している。

### 位置づけ

従来のプロンプトインジェクションが単一セッション内の一時的な挙動改変にとどまるのに対し、MemGhostは「永続性」を攻撃に持ち込む点で新規性がある。エージェントの記憶書き込み権限や、外部コンテンツ（メール等）からの指示をメモリに反映する前の検証プロセスの欠如が根本原因とされる。

### 対策の方向性

研究者らは、エージェントの記憶書き込み操作に対する監査ログの可視化、外部コンテンツ由来の指示とユーザー由来の指示の分離、メモリ更新前の確認プロンプトの導入などを推奨している。
