# Unit 42、Windows上のマルウェアがGoogle同期パスキーを乗っ取る「Pass-ta-key」攻撃を報告

- **日付**: 2026-08-10
- **出典**: [The Hacker News](https://thehackernews.com/2026/08/google-password-manager-attacks-could.html)
- **トピック**: [Google Password Manager パスキー乗っ取り「Pass-ta-key」攻撃（2026年）](../topics/google-passkey-pass-ta-key-attack-2026.md)
- **分類**: 新規

## 概要

Palo Alto Networks傘下のUnit 42は、Windows端末上で通常ユーザー権限で動作するマルウェアが、Chrome/Google Password Managerのクラウド認証機能に保存された同期パスキーを乗っ取れる3つの攻撃手法「Pass-ta-key」「Silver Pass-ta-key」「Golden Pass-ta-key」を報告した。パスワードレス認証の要であるパスキーが、端末侵害を前提とした攻撃に対して脆弱であることを示す研究であり、TPM搭載Windows環境が対象となる。

## 詳細

### 研究概要

パスキー（FIDO2/WebAuthn準拠の公開鍵暗号ベースの認証方式）は、フィッシング耐性を持つパスワードレス認証として急速に普及している。しかしUnit 42の研究では、端末上で動作するマルウェアが、Google Password Managerがクラウド同期するパスキーの秘密鍵を狙う3種類の攻撃手法を実証した。

### 3つの攻撃手法

1. **Pass-ta-key**: マルウェアが有効な認証アサーション（署名済み認証応答）をひそかに取得し、攻撃者側でそのセッションを再利用する
2. **Silver Pass-ta-key**: 攻撃者が制御するユーザー検証キーをGoogle Password Managerにインストールし、以降の認証を攻撃者が代行できるようにする
3. **Golden Pass-ta-key**: 同期パスキーの秘密鍵を復号するために使われる32バイトの「Security Domain Secret（SDS）」自体を抽出し、パスキーそのものを完全に窃取する

### 前提条件

これらの攻撃はいずれも、対象端末上でマルウェアが既に一般ユーザー権限で実行されていることを前提とする。対象はWindows上のChromeブラウザに保存されたGoogle Password Managerの同期パスキーで、かつTPM（Trusted Platform Module）を搭載した環境に限定される。ブラウザやOSの脆弱性を突く必要はなく、既存のマルウェア感染から一歩進んでパスキーを窃取する「ポスト侵害」攻撃という位置づけ。

### 現状の悪用状況

2026年8月7日時点で、これらの手法が実際の攻撃で悪用されているという公開された証拠は確認されていない。あくまで研究段階での概念実証だが、パスキーの「フィッシング耐性」が端末侵害後は無力化されうる点を示した点で注目されている。

### パスワードレス認証への示唆

パスキーはフィッシングに対しては強力な防御となる一方、端末そのものがマルウェアに侵害された場合には、従来のパスワードと同様に窃取・悪用されうることが改めて示された。エンドポイントセキュリティの重要性がパスキー普及後も変わらないことを裏付ける研究といえる。

### 推奨対策

- エンドポイント保護（EDR/アンチマルウェア）を強化し、端末侵害そのものを防ぐ
- TPMのファームウェア・OSを最新状態に保つ
- 可能であればハードウェアセキュリティキー（物理FIDO2キー）など、端末非依存の認証方式の併用を検討する
- 組織はGoogle Password Manager以外のパスキー管理方法（エンタープライズ向けパスキー管理ソリューション等）の採用も検討する
