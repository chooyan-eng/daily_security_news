# 新種モジュラー型RAT「Abyssos」、Cookie注入でWebセッションを乗っ取り隠密VNCも提供

- **日付**: 2026-08-20
- **出典**: [Zscaler ThreatLabz](https://www.zscaler.com/blogs/security-research/abyssos-technical-analysis-new-modular-rat) / [GBHackers](https://gbhackers.com/abyssos-rat-hijacks-browser-sessions/) / [Cybersecurity News](https://cybersecuritynews.com/abyssos-rat-rdpwrap/amp/)
- **分類**: 関連

## 概要

Zscaler ThreatLabz が、2026年6月下旬に初観測した新しいモジュラー型RAT「Abyssos」の技術解析を公開した。C++で書かれ、AES-GCM で暗号化した独自TCPプロトコルでC2と通信する。特徴的なのはブラウザセッションの乗っ取り機能で、盗んだCookieをChromeのデバッグ機能経由で新規インスタンスに注入することで、パスワードやMFAを再度突破することなく被害者のWebセッションを引き継ぐ。隠密VNC（HVNC）、認証情報窃取、キーロギング、RDPWrap関連モジュールも備える。

## 詳細

### 全体像

Abyssos は侵害後（post-compromise）フェーズで使われるモジュラー型のリモートアクセスツールである。中核となるローダーは最小限の機能のみを持ち、C2サーバーから追加モジュールをダウンロードして能力を拡張する設計になっている。複数のバージョン番号と異なる難読化パスが観測されており、検知回避を目的とした活発な開発が継続しているとみられる。

主な機能セットは以下の通り。

- リモートシェル
- 隠密VNC（HVNC）による遠隔デスクトップ操作
- ファイルシステム操作・ファイル持ち出し
- ブラウザデータ収集（Chrome / Firefox の認証情報、Cookie）
- キーロギング
- プロセス制御
- ネットワークスキャン
- 追加モジュールのダウンロード

### ブラウザセッション乗っ取りの手口

Webアプリケーションのセキュリティ観点で最も重要なのがこの機能である。

1. `HVNC_CLONE_START` コマンドで、ブラウザのCookieを含むプロファイルデータを Windows の一時ディレクトリ配下の `fontconfigs` という名前のフォルダへ複製する
2. `HVNC_PROG` コマンドで、Chrome のデバッグ用オプションを指定した新しいインスタンスを起動し、複製した Cookie を注入する
3. 攻撃者は隠密VNCセッション内でそのブラウザを操作し、被害者の認証済みWebセッションをそのまま利用する

この経路では、攻撃者はパスワードを知る必要も、多要素認証を突破する必要もない。セッションCookieそのものが認証の実体であるため、有効期限内であればアカウントを自由に操作できる。

隠密VNCセッション内では Chrome、Edge、Firefox、Brave、Opera、Vivaldi といった主要ブラウザに加え、メールクライアントやコマンドシェルも起動可能で、被害者の画面には何も表示されないまま操作が行われる。

### C2通信

Abyssos は独自のTCPベースのプロトコルを用いる。送受信データの大部分はハードコードされた32バイト鍵による AES-GCM で暗号化される。一部のダウンロードモジュールでは AES-CBC あるいは XOR ベースの復号が使われており、モジュールごとに保護方式が異なる。

### RDPWrap モジュール

`RDPWRAP` という名称のモジュールが確認されており、Zscaler はOSSの RDP Wrapper プロジェクトとの関連を指摘している。RDP Wrapper は本来サポートされていないWindowsエディションでリモートデスクトップのホスト機能や同時セッションを有効化するツールであり、攻撃者にとっては正規のRDP経路での持続的アクセスを確保する手段となる。

### 防御側の観点

セッションCookieの窃取と再利用はMFAを迂回するため、パスワード変更だけでは対処にならない。Webアプリケーションの提供側・利用側それぞれで以下が有効となる。

**アプリケーション提供側**
- セッションを端末やネットワーク特性に紐づけ、Cookieが別環境で提示された場合に再認証を要求する（デバイスバインディング、トークンバインディング）
- 重要操作（決済、権限変更、メール転送設定の変更等）で再認証を必須にする
- 同時セッションの異常（短時間での地理的に離れたIPからのアクセス）を検知しセッションを失効させる
- 侵害の疑いがある場合に全セッションを一括失効させる管理機能を用意する

**利用組織側**
- Chrome の `--remote-debugging-port` 系オプションを伴う起動や、ユーザーデータディレクトリの複製をEDRで検知する（本手法は Chrome DevTools Protocol を悪用するセッションハイジャック手法と同系統である）
- `%TEMP%\fontconfigs` のような不審なブラウザプロファイル複製先の監視
- インシデント対応時にパスワードリセットだけでなくセッショントークンの失効を必ず実施する
