# 「EvilTokens」：ブラウザ内復号で正体を隠す新型「ゴーストフィッシング」がMicrosoft 365を標的に

- **日付**: 2026-07-09
- **出典**: [The Hacker News](https://thehackernews.com/2026/07/new-ghost-phishing-wave-is-breaking.html)
- **トピック**: [デバイスコードフィッシング / AiTM セッショントークン窃取（2026年）](../topics/device-code-phishing-aitm-2026.md)
- **分類**: 続報

## 概要

米欧の企業を標的とする「EvilTokens」フィッシングキャンペーンが、AES-GCMで暗号化しブラウザ内で復号されるまで正体を隠す「ゴーストフィッシング」という新手法を用いていることが判明した。手口自体はMicrosoft Device Code Authenticationを悪用してMicrosoft 365アカウントへのアクセス権限を騙し取るもので、既存のデバイスコードフィッシング／AiTM攻撃の技術トレンドに沿った続報である。従来のURL静的解析では検知が困難とされる。

## 詳細

EvilTokensは、コンサルティング・金融サービス・製造業・テクノロジー・銀行・教育・MSSP等、幅広い業種の米欧企業を標的にしているキャンペーンである。攻撃の核心は正規のMicrosoft Device Code Authenticationフローを悪用する点にあり、被害者に正規のMicrosoftログイン画面上で「デバイスコード」の入力を促すことで、認証情報を盗むことなく攻撃者に対してMicrosoft 365アカウントへのアクセス権限を付与させてしまう。これは本トピックで継続的に追跡しているOAuth 2.0 Device Authorization Grant悪用型AiTM攻撃と同一の技術基盤である。

EvilTokensが新規性を持つのは「ゴーストフィッシング」と呼ばれる隠蔽手法にある。フィッシングページのHTMLはAES-GCMで暗号化された状態で配信され、ブラウザ側で復号・DOMへのレンダリングが行われるまでコンテンツが実体化しない。このため、従来型の静的URL解析やクローラーベースのスキャンでは、復号後にしか出現しない悪意あるコンテンツを検知できず、「無害なリンク」と誤判定されるリスクが指摘されている。

対策としては、ブラウザレンダリング後の挙動を観測できるブラウザアウェアな解析・サンドボックス技術の導入、FIDO2セキュリティキー等のフィッシング耐性認証への移行、Conditional Accessポリシーの活用、そして不審なDevice Code Authenticationリクエストの監視が挙げられている。従業員に対してはデバイスコードフィッシングの手口を周知し、想定外のMicrosoft認証プロンプトを速やかに報告する体制整備が推奨されている。

本トピックでは2026年5月にFBIが警告を発出し、6月には検出件数が37倍に急増、18種類のフィッシングキットが登場するなど急速なコモディティ化が確認されていたが、EvilTokensはその延長線上にある新しい実装であり、検知回避手法の高度化という点で技術トレンドが更新されたことを示している。
