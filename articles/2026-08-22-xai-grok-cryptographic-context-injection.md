# xAIのGrokチャットエージェント、暗号化ペイロードによるプロンプトインジェクション「Cryptographic Context Injection」に脆弱

- **日付**: 2026-08-22
- **出典**: [The Hacker News](https://thehackernews.com/2026/08/new-cryptographic-context-injection.html) / [SecurityWeek](https://www.securityweek.com/encrypted-prompts-bypass-ai-safety-guardrails-in-grok-and-gemini/)
- **トピック**: [xAI Grok「Cryptographic Context Injection」攻撃（2026年）](../topics/xai-grok-cryptographic-context-injection-2026.md)
- **分類**: 新規

## 概要

xAIのWebチャットエージェント「Grok」に、暗号化された命令文をWebページに埋め込みAIに復号・実行させる新種のプロンプトインジェクション手法「Cryptographic Context Injection」が存在すると研究者が公表した。ユーザー名、おおよその位置情報、サブスクリプション種別、チャット履歴などが攻撃者のサーバーへ送信される恐れがあるが、2026年6月の報告から2026年8月19日時点まで未修正のままとなっている。

## 詳細

### 攻撃の仕組み

Cryptographic Context Injectionは、攻撃者が用意したWebページ内にAES-256-GCMで暗号化されたペイロードと復号鍵を埋め込み、Grokがそのページを閲覧・処理する際にペイロードを復号して実行してしまう手法である。Grokのガードレール（安全性スキャナー）は暗号化された文字列の中身を読み取れないため、悪意ある命令がそのままスキャンをすり抜けてモデルに渡される。モデル自身のサンドボックス内で復号された命令は、通常のプロンプトインジェクション対策では検知が難しい。

### 情報持ち出しの範囲

この手法により持ち出される恐れがある情報として、ユーザー名、おおよその位置情報、サブスクリプションの種別（無料／有料プラン等）、そしてGrokとのやり取りの全チャット履歴が挙げられている。攻撃者が用意した悪意あるWebページを閲覧するだけで攻撃が成立しうる、いわゆるゼロクリックに近い性質を持つ。

### 報告から未修正までの経緯

本脆弱性は2026年6月3日にxAIへ最初に報告されたが、研究者（Utevsky氏）はその後2026年8月4日および8月10日にも再度連絡を行ったものの、2026年8月19日時点で修正時期の見通しは示されていない。約2か月半にわたり対応が行われていない状態が続いている。

### 他のAIサービスへの影響

同種の暗号化プロンプトによるガードレール回避手法は、Grokだけでなく他の大規模言語モデルベースのAIチャットサービス（Geminiなど）にも影響しうるとの指摘がある。ガードレールが平文の悪意あるパターンを検出する設計に依存している場合、暗号化やエンコードによって容易に回避されうるという構造的な課題が背景にある。

### 対応上の留意点

- Webページを開かせてAIエージェントに処理させる機能（ブラウジング機能、要約機能等）を持つAIサービスの利用時は、未知のWebページを不用意に読み込ませない
- 企業がAIチャットエージェントを業務利用する場合、外部Webコンテンツの自動処理機能を無効化または制限する運用を検討する
- ベンダー側のガードレール実装が、暗号化・エンコードされたペイロードに対しても有効に機能するかを継続的に評価する
