# 1Password、従業員のGitHubアカウント侵害からバックエンドに不正コードを投入され顧客メタデータが流出

- **日付**: 2026-11-25
- **出典**: [1Password Blog](https://1password.com/blog/update-on-nov-2026-security-incident) / [AppleInsider](https://appleinsider.com/articles/26/11/25/what-to-watch-for-after-the-new-1password-data-breach)
- **トピック**: [1Password 従業員GitHubアカウント侵害・顧客メタデータ流出（2026年11月）](../topics/1password-github-incident-2026.md)
- **分類**: 新規

## 概要

パスワードマネージャの1Passwordは、従業員の業務用GitHubアカウントが侵害され、攻撃者がバックエンドサービスに不正なコードをプッシュして一部顧客の氏名・メールアドレス・アカウントメタデータを取得したと公表した。招待・リカバリ用リンクのトークンの一部も複製された。保管庫（Vault）の内容、アカウントパスワード、Secret Keyへのアクセスはなかったとしている。

## 詳細

### 経緯

- 11月19日、従業員の業務用GitHubアカウントへの不正アクセスの兆候を検知し、調査を開始
- 攻撃者は当該アカウントを使ってバックエンドサービスに不正コードをプッシュし、そのコードが管理系の顧客データを取得した
- 非公開ソースコードの複製と、CI/CDシステムへのアクセスも確認されている
- 従業員のGitHub認証情報がどのように侵害されたかは公表されていない

### 流出した情報

- 一部ユーザーの氏名、メールアドレス、アカウントメタデータ
- メールで送信された招待リンク・リカバリリンクのトークンの一部
- 影響を受けた顧客数は非公表

### 流出していないとされる情報

- Vaultの内容、アカウントパスワード、Secret Key
- 顧客アカウントの乗っ取りの証拠は見つかっていない

1PasswordのVaultはクライアント側で暗号化され、サーバは復号鍵を持たない設計であるため、バックエンドが侵害されてもVaultの中身は直接は読めない。一方で、バックエンドに不正コードを入れられる状態は、設計上の保護の外側にある情報（メタデータ、招待・リカバリのフロー）には手が届くことを意味する。

### 1Passwordの対応

- 当該GitHubアカウントの無効化、窃取されたトークンの失効、露出した認証情報のローテーション
- 招待コード・リカバリコードの長さを拡張
- 検知ルールの追加
- 影響ユーザーへメールで通知

### 利用者側の対応

設定変更は不要とされているが、身に覚えのない招待・リカバリ要求に注意すること。また、流出した氏名・メールアドレスを使った1Passwordを騙るフィッシングの増加が見込まれる。

### 開発者視点のポイント

「開発者1人のGitHubアカウント → 本番で動くコードの改変」という経路が成立した点が本質である。ブランチ保護と必須レビュー、本番デプロイの承認分離、CI/CDシークレットのスコープ最小化、フィッシング耐性のあるMFAといった対策が、開発者アカウント侵害の影響範囲を限定する。直近ではTodoistでもバージョン管理システムの認証情報窃取を起点とする侵害が公表されており、開発基盤が主要な侵入口になっている。
