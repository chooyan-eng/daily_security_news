# バックドア「C2Looper v2」、GitHubリポジトリを丸ごとC2インフラとして悪用

- **日付**: 2026-08-18
- **出典**: [GBHackers](https://gbhackers.com/c2looper-v2-uses-github/)
- **トピック**: [C2Looper GitHub悪用バックドア（2026年）](../topics/c2looper-github-c2-backdoor-2026.md)
- **分類**: 新規

## 概要

Rust製バックドア「C2Looper」の新バージョンv2は、従来のHTTPベースC2エンドポイントを完全に廃止し、GitHubリポジトリそのものを指令送受信の運用基盤として利用する手法を採用していることが判明した。感染ホストごとに専用リポジトリが割り当てられ、3種のJSONファイルを介してタスクの送受信とビーコン管理を行う。ランサムウェア関連の脅威アクターとの関連が指摘されている。

## 詳細

### C2Looperの概要

C2LooperはZscaler ThreatLabzが2026年7月に確認したRust製の新種バックドアで、ランサムウェア関連の脅威アクターとの関連が低〜中程度の確度で指摘されている。複数段階からなる「ClickFix」型の感染チェーンを通じて配布されているとみられる。

### GitHubベースのC2アーキテクチャ

v2の最大の特徴は、攻撃者が管理するC2ドメインやHTTPエンドポイントを一切使わず、GitHubリポジトリを完全な運用バックエンドとして利用する点にある。感染した端末ごとに専用のリポジトリディレクトリが割り当てられ、以下の3種類のJSONファイルでタスクの送受信を行う。

- `cmd.json`：保留中の命令
- `result.json`：コマンド実行結果
- `beacon.json`：ボットの識別子と最終応答タイムスタンプ

### この手法の利点（攻撃者視点）

GitHubという正規かつ信頼された高可用性のWebサービスをタスク送受信・データ交換の基盤として使うことで、防御側がブロック・シンクホール化・相関分析しやすい攻撃者専用C2ドメインへの依存を排除できる。検知の観点は、開発関連の業務上の必要性がない端末からの、異常なGitHub APIアクセスやリポジトリアクセスへとシフトすることになる。

### v2で追加された機能

バージョン2では、偵察情報の収集、ドライブの列挙、シェルコードインジェクション、ファイル一覧取得といった新たなコマンドが追加されている。

### 防御上の示唆

企業は、開発業務に関与しないエンドポイントからのGitHub API・リポジトリへのアクセスを異常として検知する仕組みの導入を検討すべきである。また、正規クラウドサービスをC2として悪用する手法は今後も拡大が見込まれるため、ネットワーク境界でのドメイン・IPベースの検知だけに依存しない多層的な監視体制が求められる。
