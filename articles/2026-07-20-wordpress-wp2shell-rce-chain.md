# wp2shell（CVE-2026-63030 + CVE-2026-60137）– WordPress コア REST API 脆弱性チェーンで未認証RCEが野放しで悪用

- **日付**: 2026-07-20
- **出典**: [The Hacker News](https://thehackernews.com/2026/07/new-wp2shell-wordpress-core-flaw-lets.html)
- **トピック**: [WordPress wp2shell REST API 脆弱性チェーン（2026年7月）](../topics/wordpress-wp2shell-rce-2026.md)
- **分類**: 新規

## 概要

WordPressコアに存在する2つの脆弱性CVE-2026-63030（REST APIバッチルート処理の混乱）とCVE-2026-60137（WP_Queryのauthor__not_inパラメータにおけるSQLインジェクション）を連鎖させることで、未認証の攻撃者がWordPress 6.9〜7.0.1のサイトで匿名アクセスから管理者権限奪取・リモートコード実行（RCE）まで到達できる「wp2shell」と呼ばれる攻撃チェーンが確認された。7月17日にパッチが公開され、WordPress.orgは対象サイトへの強制自動更新を有効化している。

## 詳細

### 脆弱性の技術詳細

**CVE-2026-63030**: WordPress 6.9で導入されたREST APIバッチルート（`/wp-json/batch/v1`）処理における route confusion（ルート混乱）の脆弱性。特定のバッチリクエストを送信するとエラー条件により内部のバッチ処理の整合性が失われ、後続のサブリクエストが本来とは異なるルートハンドラのコンテキストに関連付けられてしまう。

**CVE-2026-60137**: WP_Queryの`author__not_in`パラメータに存在するSQLインジェクション脆弱性。WordPress 6.8.0〜6.8.5では単独のSQLインジェクション問題として存在する。

### 攻撃チェーンの流れ

1. 匿名の攻撃者がパブリックなWordPress REST APIエンドポイント（`/wp-json/batch/v1`）にアクセス
2. 特殊に細工したバッチリクエストを送信し、内部のバッチ処理のブックキーピングの整合性を破壊
3. 後続のサブリクエストが誤ったルートハンドラのコンテキストと関連付けられる
4. この「混乱」した処理コンテキストにより脆弱なWP_Queryの挙動が露出
5. 攻撃者が制御するクエリ内容がSQL構築パスに到達し、SQLインジェクションからコード実行まで昇格可能

### 影響範囲

- CVE-2026-63030とCVE-2026-60137を連鎖させた場合: WordPress 6.9.0〜7.0.1で未認証RCEが可能
- CVE-2026-60137単体: WordPress 6.8.0〜6.8.5で影響（SQLインジェクションのみ）
- デフォルトインストールで、無権限の匿名アクセスから「不正な管理者」権限とコード実行まで到達可能

### 対応状況

- パッチは2026年7月17日にリリース
- WordPress.orgはサポート対象の影響を受けるバージョンを実行しているサイトに対し、強制自動更新を有効化
- 複数のセキュリティベンダー（Rapid7、Wordfence系ラボ、Rescanaなど）が積極的な悪用試行のアラートを発出

### リスク評価

WordPressはWeb上のCMSシェアで圧倒的なシェアを持つため、本脆弱性チェーンは影響範囲が極めて広い。REST APIのバッチエンドポイントという比較的新しい機能（WordPress 6.9で導入）に起因する不具合であり、最新版へのアップデートを怠っているサイト運営者にとって重大なリスクとなる。自動更新の対象外となるカスタマイズ環境やマネージドホスティング以外の自己管理サイトは、手動での即時パッチ適用が強く推奨される。
