# サイバーセキュリティクラウド、従業員のGitHub認証情報流出で顧客情報漏えいのおそれ

- **日付**: 2026-11-13
- **出典**: [ITmedia NEWS](https://www.itmedia.co.jp/news/article/2611/13/2000003163/)
- **トピック**: [サイバーセキュリティクラウド GitHub認証情報流出事案（2026年11月）](../topics/cyber-security-cloud-github-breach-2026.md)
- **分類**: 新規

## 概要

WAFなどを提供するサイバーセキュリティクラウドは11月12日、従業員が業務で使用していたGitHubの認証情報1件が外部に流出し、それを用いたとみられる不審なアクセスがあったと公表した。一部顧客の企業名・氏名・メールアドレスや通信関連情報が漏えいしたおそれがある。

## 詳細

### 経緯

- 外部機関からの情報提供により、従業員が業務で使っていたGitHubの認証情報1件が外部に流出していることを把握。
- 11月5日: 当該認証情報を使ったとみられる不審なアクセスが過去にあったことを確認。ログの制約により、全期間のアクセス状況は把握できていない。
- 11月12日: 第一報を公表。

### 影響

- 漏えいのおそれがある情報: 一部顧客の企業名、氏名、メールアドレス、通信関連情報。件数は調査中で未公表。
- 本件に起因するサービスへの不正アクセス・不正操作・二次被害は確認されておらず、サービスは通常どおり提供。

### 対応

認証情報の無効化、開発端末の隔離、外部専門機関によるフォレンジック調査、個人情報保護委員会への報告を実施。同社は「セキュリティ企業として重く受け止める」とコメントしている。

### 技術的な補足

開発基盤（GitHub）のリポジトリやIssue、CI設定等に顧客情報や通信ログが含まれていたことが、顧客情報の漏えい懸念につながっているとみられる。流出経路（インフォスティーラー感染、トークンの誤公開など）は公表されていない。

同時期には、窃取されたGitHubトークンを使ってCIシークレットを盗む「wfx-loot」キャンペーンも報告されているが、本件との関連は示されていない。

教訓:

- リポジトリに顧客データ・通信ログ・本番シークレットを置かない（シークレットスキャンとpush protectionの有効化）。
- PATは細粒度・短期限にし、SSO強制と端末紐付けを行う。
- GitHubの監査ログは保持期間が限られるため、外部SIEMへストリーミングして長期保管する（今回も「ログの制約」で全容把握が難航）。
