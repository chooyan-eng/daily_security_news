# VMware vCenter の CVE-2026-59310 悪用、中国系アクターによるBabuk派生ランサムウェア展開が判明

- **日付**: 2026-08-20
- **出典**: [The Hacker News](https://thehackernews.com/2026/08/suspected-china-nexus-actor-exploits.html) / [Dark Reading](https://www.darkreading.com/vulnerabilities-threats/global-threat-campaign-critical-vmware-vcenter-flaw) / [Cyber Press](https://cyberpress.org/chinese-actors-weaponize-vcenter/)
- **トピック**: [VMware vCenter/ESX 重大脆弱性 VMSA-2026-0006（2026年）](../topics/vmware-vcenter-esx-critical-vulnerabilities-2026.md)
- **分類**: 続報

## 概要

VMware vCenter Server のディレクトリトラバーサル脆弱性 CVE-2026-59310（CVSS 9.8）を悪用する大規模キャンペーンについて、攻撃者が中国語話者とみられる脅威アクターであること、そして root 権限奪取後に複数のバックドアを設置し、ディレクトリ認証情報を窃取したうえで ESXi ハイパーバイザに Babuk 派生のランサムウェアを展開していたことが明らかになった。QUIRSO は47カ国・361のユニークな被害IPを特定しており、CISA は8月18日に本脆弱性を KEV カタログへ追加、連邦機関に8月21日を期限とする是正を求めている。

## 詳細

### 前提となる脆弱性

CVE-2026-59310 は、VMware vCenter Server の Syslog Server コンポーネントにおけるディレクトリトラバーサル（CWE-22）である。Broadcom が VMSA-2026-0006 として2026年7月29日に公開し、CVSS 9.8 の Critical と評価した。ネットワーク到達可能な攻撃者が認証なしに任意コードを実行できる。

### 攻撃チェーンの詳細

今回明らかになった侵害後の活動は以下の通りである。

**1. 初期侵入と権限取得**

Syslog のパストラバーサルを利用して `/etc/cron.d` 配下に不正な cron ファイルを書き込む。cron が定期実行する場所にファイルを配置することで、通常のログインを経ずに root としてコマンドを実行する。

**2. 永続化**

OSSツール reverse_ssh を用いた C2 への逆方向SSH接続を確立する。これにより攻撃者は、被害環境のファイアウォールがインバウンドを遮断していても継続的にアクセスできる。

**3. Webシェルの設置**

`vmware-perf-update.jsp` という名称のJSP Webシェルを設置する。正規の VMware コンポーネントを装った命名であり、認証情報の窃取に使われた。

**4. 認証情報の窃取**

レジストリ照会および Python スクリプトを用いて vCenter のマシン認証情報を抽出し、外部へ持ち出す。vCenter は仮想化基盤全体の管理権限を持つため、ここでの認証情報窃取は環境全体の掌握に直結する。

**5. ESXi へのランサムウェア展開**

窃取した認証情報を用いて ESXi ホストへ横展開し、Babuk 派生のランサムウェアで暗号化する。暗号化後のファイルには `.babyk` 拡張子が付与される。ハイパーバイザ層での暗号化は、その上で稼働する全ゲストVMを一括して停止・破壊するため、被害の即時性と規模が大きい。

**6. 検知回避**

`GoodMoodle-VCFleet/1.0` といった User-Agent 文字列を用いて VMware の正規ツールを装い、通信の異常検知を回避しようとしていた。

### 攻撃者の推定

研究者が中国系グループの関与を疑う根拠として、以下が挙げられている。

- スクリプト内に中国語の痕跡（コメント・文字列）が存在する
- 中国のセキュリティ系媒体に掲載された研究内容の再利用とみられる実装が含まれる
- 中国語圏のツール・ソフトウェアが繰り返し使用されている
- 中国本土に被害者が確認されていない

なお研究者は、ランサムウェアの展開が本キャンペーンの主目的であったとは限らないとの見方も示している。バックドア設置と認証情報窃取が先行していることから、諜報目的の侵入がまずあり、ランサムウェアは撤収時の痕跡撹乱あるいは副次的な収益化であった可能性がある。

### 展開の速度と規模

- 2026年7月29日: Broadcom が VMSA-2026-0006 を公開
- 2026年8月3日: 最初の侵害システムが攻撃者インフラへ通信を開始（開示からわずか5日）
- 2026年8月5日時点: QUIRSO が47カ国で361の被害IPを観測、うち約95%（343台）が既に侵害済み
- 2026年8月18日: CISA が KEV カタログへ追加
- 2026年8月21日: 連邦民間行政機関に対する緩和措置の期限

被害が確認された分野には、テクノロジー、研究、教育、通信の各セクターが含まれる。

### 対応

暫定的な回避策は存在せず、パッチ適用が唯一の対策である。対象は vCenter Server 8.0 U3k、VMware Cloud Foundation / vSphere Foundation 9.1.0.0300 および 9.0.2.0100 以降。

すでにパッチを適用済みであっても、7月29日以降にvCenterがインターネットに露出していた環境では侵害済みの前提で以下を確認する必要がある。

- `/etc/cron.d` 配下に不審な cron ファイルがないか
- `vmware-perf-update.jsp` をはじめとする想定外のJSPファイルが存在しないか
- reverse_ssh に相当するアウトバウンドSSH接続の痕跡
- `GoodMoodle-VCFleet/1.0` 等の異常な User-Agent を含む通信ログ
- vCenter マシン認証情報および連携するディレクトリ認証情報のローテーション実施

パッチ適用のみでは、既に設置されたバックドアと窃取済みの認証情報は無効化されない点に注意が必要である。
