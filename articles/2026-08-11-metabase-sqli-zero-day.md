# Metabase 認証不要SQLインジェクション・ゼロデイ（CVSS 10.0）が実悪用、管理者権限奪取が可能に

- **日付**: 2026-08-11
- **出典**: [The Hacker News](https://thehackernews.com/2026/08/metabase-zero-day-exploited-in-wild.html)
- **トピック**: [Metabase SQLインジェクションゼロデイ（CVSS 10.0、2026年8月）](../topics/metabase-sqli-zeroday-2026.md)
- **分類**: 続報
## 概要

BIツール Metabase（v1.58以降）に存在する未認証SQLインジェクションのゼロデイ脆弱性（CVSSスコア10.0、CVE番号未採番）が実際の攻撃で悪用されていることが判明した。未認証の攻撃者が `/api/session/reset_password` エンドポイント経由で任意のSQLを注入し、管理者権限を奪取できる。

## 詳細

### 脆弱性の内容

脆弱性は Metabase アプリケーションの未認証エンドポイント `POST /api/session/reset_password` に存在し、攻撃者はここに細工したリクエストを送信することで任意のSQLをアプリケーションデータベースへ注入できる。取得した管理者権限を悪用すると、アプリケーション設定の変更、接続先データベースの認証情報窃取、当該データベース経由でアクセス可能な全データの閲覧・エクスポートが可能になる。

### 悪用状況

本脆弱性は実際の攻撃キャンペーンで悪用されており、複数の企業が顧客データ窃取被害を公表している。ワークフロー自動化プラットフォームの n8n は2026年8月8日、本脆弱性経由で136件の顧客レコード（氏名・メールアドレス）が窃取されたと発表した。PCメーカーの Framework も同様の手口で顧客の氏名・ログインIP・住所・電話番号・メールアドレスが窃取されたことを確認している。他にも Kilo Code など複数の組織が影響を受けたとみられる。

### 対応・パッチ

セルフホスト版の安全な最小バージョンは 0.58.24、0.59.21、0.60.17、0.61.11、0.62.9、0.63.5 とされている。即時パッチ適用が困難な場合の暫定対策として、`/api/session/reset_password` エンドポイントのブロックによる露出低減が推奨されている。
