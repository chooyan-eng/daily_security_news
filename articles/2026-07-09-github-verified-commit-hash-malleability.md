# GitHubの「Verified」署名付きコミット、署名を壊さずハッシュを書き換え可能と判明

- **日付**: 2026-07-09
- **出典**: [The Hacker News](https://thehackernews.com/2026/07/github-verified-commits-can-be.html)
- **トピック**: [GitHub署名付きコミットのハッシュ可鍛性（2026年7月）](../topics/github-commit-signature-malleability-2026.md)
- **分類**: 新規

## 概要

カーネギーメロン大学の博士課程学生でCure53の暗号監査担当でもあるJacob Ginesin氏が、GitHubで「Verified」と表示される署名付きGitコミットについて、署名鍵を持たない第三者でも同一の内容・作者・日時を保ちながら異なるハッシュ値かつ有効な署名を持つ「複製コミット」を生成できることを実証した論文をarXivに公開した。ブロックリストによる悪意あるコミットの遮断策が、ハッシュ値のみに依存している場合は回避され得ることを意味する。

## 詳細

本研究の核心は「ハッシュチェーン可鍛性（hash chain malleability）」と呼ばれる問題であり、原因は署名の可鍛性（signature malleability）にある。Gitコミットのハッシュは、ヘッダ内の署名の生バイト列を含むコミット内の全データに対して計算される。多くの署名方式では、意味的に同一だがバイト表現が異なる署名を生成できるため、署名のバイトを変えるだけでコード内容を一切変更せずにコミットハッシュを変化させることができる。

論文は、GitHubが検証する主要なGPGベースの署名方式すべてを網羅する3つの攻撃経路を示している。ECDSA署名に対しては、署名(r, s)を数学的に同等な(r, n-s)に変換する古典的な代数対称性を利用する。この変換に耐性のあるRSAおよびEdDSA署名に対しては、OpenPGP署名パケットの「署名対象外領域（unhashed region、RFC 4880で署名の対象外と規定されている領域）」に整形済みだが無視されるサブパケットを追加する手法を用いる。S/MIME署名に対しては、CMS構造内の長さフィールドを、厳密なDERとしては不正だが緩いBERとしては受理される非正規形式に再エンコードする。

研究者はこれら3つの攻撃をすべて実行できる公開ツールと、実際に改変後も「Verified」表示が維持される2つの実証リポジトリを公開している。

サプライチェーンセキュリティにおける実害は、特定のコミットハッシュを「悪意あるもの」としてブロックリストに登録する防御策が機能しなくなる点にある。攻撃者は同一内容のコミットを、ブロックリストが認識していない新たな「Verified」ハッシュの下で再度プッシュできるため、ハッシュベースの検知・遮断は迂回可能になる。GitHub側の対応状況は本記事時点では明らかになっていないが、コミット署名の一意性を前提とした既存のセキュリティ運用・ツールチェーンへの影響が懸念される。
