# Microsoft、Entra Connect Health APIの欠陥悪用によるテナントメタデータの不正取得を公表

- **日付**: 2026-11-22
- **出典**: [Neowin](https://www.neowin.net/news/after-outage-microsoft-confirms-another-july-bug-that-led-to-entra-data-breach/)
- **トピック**: [Microsoft Entra Connect Health API テナントメタデータ不正取得（2026年11月）](../topics/entra-connect-health-api-exposure-2026.md)
- **分類**: 新規

## 概要

Microsoftは、Entra Connect HealthのAPIに7月23日から存在した欠陥が悪用され、テナントID・表示名・初期ドメイン・ライセンス種別・管理者の連絡先メールなどのメタデータが読み取られたと該当テナントに通知した。11月19日にサービス側で修正済みで、認証情報の流出はないとしている。

## 詳細

各社報道によると、Microsoftは11月20日、Entra Connect Health（オンプレミスADとEntra IDの同期基盤の監視サービス）のAPIの欠陥を突いた、テナントレベルのメタデータへの不正な読み取りアクセスがあったことを、影響を受けた組織に個別通知した。欠陥は2026年7月23日に混入し、11月9日に検知、11月19日のサービス側修正で以降のクエリは遮断された。

読み取られた可能性のある情報は、テナントID、表示名、初期ドメイン名、国コード、リージョンスコープ、Entraライセンス種別、ディレクトリ同期の状態、Connect Healthのオンボード状況、および技術連絡先・管理者アカウントに紐づくメールアドレス。一部報道ではAPI応答に期限切れの証明書（pksCertificateフィールド）が含まれていたとされる。Microsoftは、パスワード、パスワードハッシュ、認証トークン、利用可能な暗号鍵は露出していないとし、不正な構成変更の証拠も見つかっていないと説明している。影響テナント数は公表されていない。また7月23日は欠陥の混入日であり、攻撃者がいつから悪用していたかは示されていない。

対応: 修正はサーバー側で完了しており顧客側のパッチは不要。Microsoftはどのメタデータ項目が露出しえたかを確認するPowerShellスクリプト（aka.ms/ConnectHealth/scripts）を公開した。通知はテナント単位のため、MSPは顧客テナントごとに確認が必要となる（[出典: SecurityOnline](https://securityonline.info/microsoft-entra-connect-health-exposure/)）。

技術的な補足: 報道内容から判断する限り、あるテナントの文脈から他テナントの情報を取得できるクロステナントの認可不備（マルチテナントAPIにおけるBOLA）に類する問題とみられるが、Microsoftは技術的詳細を公開しておらず、「未認証でアクセス可能だった」とする一部二次報道は裏付けが取れていない。流出項目に認証情報はないものの、テナントID・初期ドメイン・ライセンス種別・同期状態・管理者メールの組み合わせは、標的選定と管理者を狙ったフィッシング（デバイスコードフィッシング、同意フィッシング等）の精度を高める。Entra IDをIdPとするWeb／モバイルアプリの運営者は、管理者アカウントへのフィッシング耐性MFA（FIDO2／パスキー）の強制、条件付きアクセス、管理者宛ての不審な同意要求やサインインの監視を再確認するとよい。
