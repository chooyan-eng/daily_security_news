# Radware、Cloud WAFの内部管理APIが認証なしで公開状態に 顧客のログ出力先クラウド認証情報が露出

- **日付**: 2026-11-26
- **出典**: [SC Media](https://www.scworld.com/brief/radware-reports-data-breach-involving-exposed-cloud-management-api)
- **トピック**: [Radware Cloud WAF 管理API露出・顧客認証情報流出（2026年11月）](../topics/radware-cloud-waf-api-exposure-2026.md)
- **分類**: 新規

## 概要

Radwareは、Cloud WAFの内部管理APIが認証なしでインターネットからアクセス可能になっており、11月19日に攻撃者が侵入したと顧客に通知した。約10時間後に検知して遮断。顧客の連絡先と、一部顧客がログ出力用に登録していたAWS S3・Azure Blob Storage・SFTPの認証情報が露出した。同社は認証情報のローテーションと11月19日以降のストレージログ確認を求めている。

## 詳細

### 概要

- 発生日: 2026年11月19日。内部用の Cloud Web Application Firewall 管理APIが、認証なしでパブリックインターネットから到達可能になっていた。
- 検知: 侵入から約10時間後。Radwareは発信元IPアドレスの遮断、当該APIへのアクセス遮断、すべての内部アカウント認証情報の入れ替えを実施。現在は当該エンドポイントに認証が必要になっているとされる。
- BleepingComputerの報道（Radwareの根本原因分析に基づく）時点では、SECへの報告書提出や公式の対外声明は行われていなかったとされる。

### 露出した情報

- 顧客の連絡先情報。
- 一部顧客について、WAFログのエクスポート先として登録された AWS S3、Azure Blob Storage、SFTP の認証情報。
- RadwareはWAFの検査処理、証明書、アプリケーショントラフィック、クラウドDDoS関連データは露出していないとしている。
- 影響顧客数は非公表。攻撃者が到達したAPIキー等の顧客情報が悪用されたかは調査中。

### 顧客への推奨

- AppSec（WAF／BOT）顧客は、ログエクスポート用の認証情報をローテーションする。
- 11月19日まで遡ってストレージ側のアクセスログを確認する。実際に、見慣れないIPからログ出力先バケットへのアクセス試行についてAWSのアラートを受けた顧客がいると報じられている。

### 技術的な補足

- **セキュリティ製品の管理プレーンが攻撃面になる**: WAFはWebアプリの前段で全トラフィックを扱うため、その管理APIは高価値な標的である。今回はトラフィックや証明書への影響はないとされるが、管理APIの露出は設定改ざん（ルール無効化、オリジン変更）につながりうる類型で、未認証公開は重大な設定不備である。
- **ログ出力用認証情報のリスク**: WAFログにはリクエストURL、ヘッダー、場合によってはクエリ文字列やボディ断片が含まれ、セッショントークンや個人情報が紛れ込みやすい。出力先バケットの認証情報が漏れると、過去ログの読み取りに加え、権限設定次第では同一バケット／アカウント内の他データにも到達される。
- **対策**: SaaSに渡すクラウド認証情報は長期アクセスキーではなく、IAMロールの引き受け（AssumeRole＋External ID）やAzureのマネージドID／短期SASなど短命・限定スコープのものを使う。権限は対象プレフィックスへの書き込み（PutObject）のみに絞り、読み取り・一覧権限を与えない。ログ専用バケット／アカウントに分離する。
- 影響を受けた可能性がある場合は、CloudTrail／ストレージアクセスログで11月19日以降の未知IPからのGetObject・ListBucket等を確認する。
- 二次情報サイトにはAI生成とみられる記事も混在しているため、詳細はRadwareからの顧客通知で確認すること。
